# Docs — 文档体系入口

本目录按真实工作流排序。编号不是业务编号，而是文件树排序约定：先规划，再交付，再工程治理，最后历史兼容。

## 分层导航

| 层级 | 目录 | 职责 |
|------|------|------|
| 01 | [01-product-planning](01-product-planning/README.md) | 产品路线图、里程碑、迭代、需求池和需求塑形 |
| 02 | [02-delivery-plans](02-delivery-plans/README.md) | 已进入交付的 spec、plan 和任务实施材料 |
| 03 | [03-engineering-governance](03-engineering-governance/README.md) | 当前工作台、跨 AI 工作流、技术债、规则、复盘和验证矩阵 |
| 90 | [90-compat-legacy](90-compat-legacy/README.md) | 历史插件输出和兼容资料，不作为新任务默认事实源 |

## 使用原则

- 新需求先进入规划层；准备交付后再进入交付层。
- 规划层用于管理项目方向、里程碑、迭代和需求池；交付层仍是开发依据、验收标准和实施闭环的重心。
- 当前执行状态只进入工程治理层的工作台，不进入规划层或交付层。
- 工程规则、质量门禁、技术债和复盘都进入工程治理层。
- 历史插件输出只放在兼容层；新任务必须迁移或镜像到规划层或交付层。
- 旧顶层文档目录已完成迁移，不保留兼容入口。所有 AI IDE 和人工协作入口以本文件和根目录 `AGENTS.md` 为准。
