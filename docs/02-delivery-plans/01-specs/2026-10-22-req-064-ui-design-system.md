## 1. 设计决策与证据边界

1. TraeWork 为全站视觉主参照，覆盖外壳、导航、页面布局、字体、间距、控件、表格、表单、卡片、菜单、确认弹窗及各种状态。Doubao 为 AI 聊天区域的局部参考，覆盖输入区、消息排列、回答阅读区、消息操作与滚动体验；配色、字体和基础控件仍服从统一设计系统。确认弹窗不属于 Doubao 参考范围，使用 TraeWork 组件规则和现有 ConfirmDialog。其他库仅补充必要的信息组织，不建立独立视觉体系。
2. “完全参考”落实为可追踪的层级、尺寸节奏、控件解剖和状态规则。仓库的业务、权限、双主题、蓝色强调、Lucide 与 Vue 约束优先；差异记入参考映射，不用百分比相似度替代规则。
3. 原资料是重建/生成的设计库，不等于友商生产源码。TraeWork 是 light-only；其 dark 版本需沿用 MetaEduBase 既有深色 Token，不能声称源文件提供了深色实现。
4. Doubao 组件预览是静态 HTML；dashboard 的 `Chat()` 展示空会话居中布局、输入自动增高和建议问题，无消息历史、长回答、消息操作或阅读位置跟随实现。后四类体验纳入局部设计范围，但缺失的规则明确作为本项目适配（§4 / 矩阵 DB-03），不冒称来源已有代码，也不直接搬入 React/CDN/演示状态。
5. S0 的最高证据层级为源文件静态研究。PR #667 已为 S1a 共享外壳补充可运行预览、同条件改前/改后截图、结构化度量及前端自动验证；但其记录同时明确未建立像素级视觉回归、未做人工点击流或多 OS 字体对比。S1a 不替代 S1 全量共享控件、S2 与 S4 的后续预览和用户视觉确认，也不代表全站视觉基线已验收。
6. TD-114 完成核验与治理收口已合入 main `a6fc4877`（plan §1）；S0 规划与 S1a 共享基础分别由 #664 / #667 合入。本次规范事实同步不启动新的 UI 实现或 phase-D/E，不开放未交付发送、流式、审批或产物能力。登录页同样纳入全站视觉一致性验收与必要样式升级，保留鉴权、表单语义和项目品牌约束。

## 2. 一套设计基础

实现位置保持现有 `packages/web/src/assets/css/{themes,tokens,components,markdown}.css`。颜色由 themes 提供、语义别名由 tokens 暴露、组件组合由 `ui-*` 提供；页面不得导入参考库全局样式，也不新建平行的 `ds-*` 系统。

### 2.1 Token 映射与默认值

| 参考规则 / 源 Token | MetaEduBase Token | 本轮默认 |
|---|---|---|
| TraeWork `--bg-base-default` / `--bg-base-secondary` | `--color-bg-base` / `--surface-sidebar-bg` / `--color-bg-elevated` | 浅色画布 `#FAFAFA`、侧栏 `#F5F5F5`、输入与卡片白色；保留现有深色对应层级 |
| `--text-default` / `--text-secondary` | `--color-ink` / `--color-ink-secondary` | 正文与次要文字分别使用；可读提示不得仅用现有低对比 tertiary 色 |
| `--border-neutral-l1..l3` | `--color-border-subtle` / `--color-border` | 1px 细边界；非交互面板不因 hover 增强阴影或表现为可点击 |
| `--bg-brand` / `--border-brand` | `--button-primary-*` / `--color-accent` / `--color-accent-ring` | 沿用蓝色；绿色只表示成功，不继承其他库品牌色 |
| `--body-base-*` / `--heading-xl-*` | `--font-body` / `--text-body` / `--text-page-title` | 正文 14px/20px，页面标题 24px/32px，分节 18px，辅助文字 13px；不引入远程字体 |
| `--spacer-*` | 现有 `--spacing-page/section/card`，补充 `--spacing-control-gap` | 页边距桌面 24px、手机 16px；分节 24px，卡片 16px，控件间距 8px；共享层统一调整 |
| 数值圆角，不照搬同名别名 | `--radius-sm/md/lg/xl/full` | 6/8/12/16px/全圆；按钮/输入 8px，卡片 12px，弹窗 16px；不同库同名 `md` 不代表同一值 |
| Doubao `.composer` 的 22px 圆角、24–160px 文本区 | 新语义 `--radius-composer` / `--size-composer-input-min/max` | 外框 16px，文字区 24–160px，内边距 16px；这是有意归一化的差异 |
| 控件 / 图标 | 新 `--size-control-sm/md/touch`、`--size-icon-sm/md` | 32/36/44px；图标 16/20px；手机主要操作触控区至少 44px |
| 动效 | `--duration-fast/normal` + `--ease-out` | 150/200ms；不使用弹跳、呼吸/扫描效果；支持 reduced-motion |
| 浮层 | 现有 `--z-sidebar/drawer/dialog/toast` | 维持既有相对层级；不得在页面散落 z-index |

新增 Token 由 S1 所有者实现；存在同义值先复用。正文至少 4.5:1、大字号至少 3:1，交互边界/焦点至少 3:1；S1 需实测深浅主题，必要的色值修正仅发生在主题层并登记差异。保留历史主题值到 light 的兼容映射，不新增主题切换选项。

共享层须覆盖 default、hover、focus-visible、active/selected、disabled、loading、empty、error、success、无权限等适用状态；某状态无真实能力支撑时记录门控或不适用原因，不以静态示例补造生产状态。表格、表单、卡片、菜单和确认弹窗均以 TraeWork 组件契约/预览为视觉依据，其他库只补信息顺序。

### 2.2 页面与工作台布局

- 全局外壳填满可用窗口，不复制友商 UIKit 的 1184px 外框上限、macOS 红绿灯或产品名称。全局导航保持现有 Route meta 投影与 `activeNav` 语义。
- 页面采用“标题/说明/主操作 → 筛选/工具栏 → 内容 → 分页/状态”的固定顺序。一个区域只突出一个主操作；危险动作复用 ConfirmDialog。
- 普通页面侧栏宽 240px，表单正文最大 800px，列表和数据详情充分使用剩余宽度；宽表在自身容器横向滚动，不能撑开整个页面。
- Workspace 按其内容容器宽度决策：≥1180px 展示会话 260px + 中间 `minmax(480px,1fr)` + 详情 320px（两处 12px 间隙）；768–1179px 为会话 240px + 消息，详情以抽屉打开；<768px 为会话/消息/运行单面板 Tab，切换不卸载草稿和会话状态。
- 断点判断依据实际可用容器；全局侧栏占用空间必须计算在内。选中会话后进入消息面板，用户显式点击运行详情才切到运行面板。resize 不重建 Conversation/Run。
- 问答正文与 Composer 最大宽 800px、居中；用户消息上限为正文宽的 85%，助手正文使用整列阅读宽度。回答 16px/1.65；导航/工具仍为 14px，中文长句、代码、表格分别换行或局部滚动。
- 页面使用一条主要内容滚动轴；Composer 在布局底部占位，不依赖固定 `pb-[88px]` 猜高度。自适应输入框、手机安全区与软键盘不能挡住最后一条消息。

## 3. 组件组织及前端接口边界

先复用 PageHeader、EmptyState、ConfirmDialog、LoadingSpinner、ToastContainer、EvidenceCard、EvidenceRefLink、DocumentSourceList、TableRenderer。样式升级不得丢失原 props/events、权限判断、测试定位点和来源导航行为。

- 纯视觉规则优先沉入现有 CSS；有重复行为才增加 Vue 组件。共享控件与 Composer 由 S1 维护，后续页面不得自行复制变体。
- S1 新增共享 `UiComposer`：受控 `modelValue:string`；`mode:'ready'|'busy'|'readonly'|'unavailable'`；`canSubmit:boolean`、`canStop:boolean`、`placeholder:string`、`hint?:string`、`inputLabel:string`。事件仅为 `update:modelValue`、`submit`、`stop`，附件/工具以具名插槽提供。提交必须同时满足 `mode === "ready" && canSubmit && modelValue.trim().length > 0`，且输入法非 composing；按钮与键盘入口共用这一条件。`ready + canSubmit=false` 仍可编辑草稿，适用于当前 Workspace；`readonly` 保留可读取内容但禁止编辑/提交，`unavailable` 禁用输入并给出原因。`busy` 禁止编辑和再次提交；仅 `mode === "busy" && canStop` 时显示并允许停止。组件不请求 API、不选择模型、不管理 Conversation，也不推断租户权限。
- AI Chat 与 Workspace 保留独立容器/适配层：前者调用现有发送/中止逻辑，后者使用 workspaceDraft store 和真实能力门控。避免为了共享视觉合并两个业务 store。
- 不新增 HTTP API、DTO、数据库或 RunEvent 名称。后续 HumanInputCard、ApprovalCard、ArtifactCard 的数据接口只能在对应 REQ 契约冻结后引用其类型，本 spec 不预造第二套协议。
- 新业务文件默认 ≤500 行；遇到已有大文件只抽取本切片需要的视图/交互职责，不扩大到无关领域重构。

## 4. 问答体验：统一视觉系统 + Doubao 聊天区域局部参考

| 局部范围 | 当前原资料支持 | 本项目适配与来源边界 |
|---|---|---|
| 输入区 | DB-01 文本区/底部工具行与焦点外框；DB-02 `onInput` 自动增高至 160px、建议问题填文本 | Vue/UiComposer、16px 圆角、IME/发送/停止/草稿门控是本项目适配；不引入演示工具 |
| 消息排列 | DB-02 `.chat` / `.chat-inner` 仅为空会话居中布局，没有消息列表 | 延续局部简洁内容列方向；真实消息顺序、角色、请求身份、用户消息宽度与助手整列布局由本项目规定，记 DB-03 |
| 回答阅读区 | 现有 Doubao 包没有长回答、Markdown/代码/表格与证据样例 | 本项目统一阅读宽度与排版，保留安全 Markdown、引用和问数结果；不能声称逐项复刻 Doubao，记 DB-03 |
| 消息操作 | 原包仅有 Composer 工具，未实现消息复制/重试等操作栏 | 按本项目已交付动作提供统一轻工具栏、键盘入口和反馈；有副作用的动作服从已有契约，记 DB-03 |
| 滚动体验 | DB-02 的 `.tool-scroll` 为工具行横向滚动，不是会话跟随实现 | 阅读位置保持、回到最新、输入框占位与手机键盘避让由本项目设计并测试，记 DB-03 |

此表扩大的是聊天局部体验的设计覆盖，不扩大原资料的证据范围。所有行的配色、字体和基础控件仍取统一 Token；聊天内触发的确认弹窗也使用 TW-02 / ConfirmDialog。

### 4.1 输入与动作

| 状态 | 展示和动作 | 必须保留 / 验证 |
|---|---|---|
| 空白且可用 | 同一 Composer，发送禁用；建议问题只在空会话展示 | 不显示语音、PPT、图片生成等未提供的能力 |
| 有文本 | 文本区自动增高到 160px，超过后内部滚动；发送可用 | 空格不可提交；Enter 发送，Shift+Enter 换行，中文 IME composing 不发送 |
| 请求中 | 保留用户消息和明确的进行中状态；现有支持中止时展示停止 | 不用打字机动画伪造流式；不允许重复提交；保留原幂等身份 |
| 错误 / 超时 | 稳定错误说明，保留既有草稿恢复行为 | 不由样式组件自动重试；显式重试复用原请求身份规则，不创造第二条 Run |
| 用户停止 | 状态按真实响应/恢复凭据呈现 | HTTP abort 不等于后台 Run 已终止；不得立即显示“任务已取消” |
| Workspace 未开放发送 | 本地草稿可编辑，发送禁用且说明原因 | 仅改观感，不能去掉现有硬门禁 |
| 已归档 / 删除 / 无权限 | 只读或不可操作，与实际契约一致 | 不以视觉禁用代替服务端授权，不跨用户复用草稿 |
| 附件、工具、语音 | 仅在所属功能已交付且当前用户可用时提供入口 | 本轮不增加上传、录音或模型切换；未交付入口不画假按钮 |

建议问题沿用当前真实可回答的业务问题及点击语义，不引入娱乐推荐或虚构能力。与草稿、工具选择有关的行为变更需独立标明，不隐藏在 CSS PR 内。

### 4.2 回答、引用与滚动

- 助手回答以内容为主，减少重边框/头像占位；消息操作以统一轻工具栏呈现，有效操作可由键盘访问。
- 沿用现有安全 Markdown 渲染、链接校验和代码块规则；长表格/长 URL 仅内部滚动，不用隐藏溢出来掩盖缺失内容。
- 引用编号绑定真实 evidence ID，并保持跨消息隔离；DocumentSourceList 聚合同源文档，补充证据使用 EvidenceCard。无证据提示保留，不以视觉简化删除来源。
- 来源不可访问、失效或无权限时展示对应结果，不生成临时假引用。问数结果保留数据表、指标口径、过滤条件、来源和空结果语义；模型解释与事实区分。
- 用户在底部时跟随新消息；向上阅读后不强制拉到底部，提供“回到最新”入口。仅在真实流式能力到位时增量渲染；屏幕阅读器只播报阶段或完成摘要，不逐 token 播报。

### 4.3 Workspace 延伸

现状核验（基线 `6122d29a`）：WS-S1 已有三栏、会话读取/恢复和本地草稿，WorkspaceComposer 的发送按钮仍禁用；AI Chat 通过一次 HTTP 请求获取回答，二者不得混为同一完成状态。

现有展示先迁移；新增发送仍归 [WS-S2/WS-S3 plan](../02-plans/2026-09-09-req-042-ws-s2-ws-s3-contract-shaping.md) 与最新 phase-A/B/C/discovery、TD-114 契约。浏览器 SSE、去重/补洞、cancel/steer、审批与产物，分别等待其真实实现；旧 plan 中的历史状态不能覆盖最新工作台/合并事实。

未来可呈现 plan summary、phase、tool lifecycle、human input、approval、artifact、evidence 和错误摘要；不展示原始 Chain-of-Thought。HumanInput 是信息补充，Approval 是授权决策，使用不同标题、动作、有效期与权限表达；审批只展示服务端提供的有效选项，过期/已处理不可重复提交。UI 不自建 Run 状态机。

## 5. 业务页面与未来功能模式

| 场景 | 统一模式 | 真实业务边界 |
|---|---|---|
| 登录 | TraeWork 统一的字体/间距/控件/表单状态；保留 REQ-023 品牌标识与蓝色约束 | S7 实施必要样式升级，保持鉴权、校验、提交、错误与跳转语义；S8 做全站视觉及功能验收，不能仅以兼容回归收口 |
| 知识/资源/数据列表 | 标题、筛选栏、列表/表格、空/错/加载、分页 | 搜索、选择、上传和原详情链接继续使用现有服务 |
| 配置与管理表单 | 分组标签、字段帮助、就地错误、底部操作区 | 保存前校验；敏感字段不回显；取消不提交 |
| 详情 / 背调报告 | 标题与状态、Tabs、正文、来源/审计辅助区 | 保留制审分离与领域状态，不把报告替换成聊天消息 |
| 应用/Skill/MCP | 卡片或紧凑列表 + 筛选 + 详情 | 状态和权限来自真实 Registry；不复刻示例假计数 |
| REQ-061 Memory | 分 scope 列表、来源/有效期、查看/纠正/删除 | 不把会话记录自动升级为记忆；无契约前只写规范 |
| REQ-062 动态采集/报表 | 要求 → 覆盖分析 → 草案预览/确认 → 发布 → 填报 → 快照报告 | 缺失/异常显式显示；发布与版本冻结遵循所属契约 |
| REQ-063 外部来源 | 来源表、授权/时效状态、快照详情、冲突证据并列 | AI 摘要、来源事实、人工结论分开；无来源不编造 |

图表沿用现有 ECharts；参考库用 CSS 条形图表达的静态数值不能变成生产图表。图表必须带单位、期间、来源与无数据状态；多序列颜色是数据编码，不得借此增加品牌主题。

每个未来需求在 spec 中补一行“页面模式、已有组件、完整状态、权限动作、证据入口、参考 ID、桌面/手机验收”。如确需新模式，由共享层负责人更新本规范；不允许页面 Agent 临时自建主题或复用未经映射的友商 CSS。

## 6. 一致性与质量验收

- 每个切片建立可审查链：参考库路径+hash → selector/行为 → 采用/适配差异 → Token → Vue 组件/页面 → fixture/截图/交互测试。表述“参考 TraeWork”不能替代这条记录。
- 保留以下三类视觉确认节点，由用户查看**可运行预览与同条件截图**后确认，才能批量扩展对应样式。代码检查通过不能代替用户视觉确认；S0 只定义节点，S1a 的截图交付不替代 S1 全量共享控件与 S2/S4 节点验收。

| 节点 | 可运行预览与截图范围 | 确认后的扩展边界 |
|---|---|---|
