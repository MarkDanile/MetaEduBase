## 使用规则

迭代文件按**用途**分为三类，保留口径不同。**文件数量不能单独作为删除依据。**

| 用途 | 适用文件 | 保留口径 |
|------|----------|----------|
| 当前及近期迭代窗口 | 进行中迭代，以及刚结束的 1 到 2 个迭代 | 作为排期与任务入口保留完整文件；结束后移入「最近关闭」段 |
| 历史摘要 | 更早的已结束迭代 | 可只保留摘要与链接，详细交付事实进入 work-log、PR、spec 或 plan |
| 长期冻结契约 | 承载唯一详细架构 / 产品冻结事实的迭代文件 | **必须保留原文件**；确需精简时，先把冻结事实完整迁移到 spec、plan 或 milestone，再执行清理 |

- 判断某个迭代文件能否删除时，先核对三项：是否承载其它事实源没有的详细冻结事实、是否被其它事实源引用、是否仍具历史交接价值；三项均为否才可移除。
- **2026-W30 必须保留**：该文件的 AG-1 至 AG-8 架构冻结表与 Product Decisions 是 P3 架构契约的唯一详细事实源，milestone 与 backlog 均无同等明细，不得以「已结束」为由删除或剥离。
- **2026-W23 与 2026-W25 当前保留完整文件**：两者仍具历史交接价值，并被本目录「最近关闭」段引用；在完成事实迁移前不得删除。
- 迭代内任务必须指向 backlog、技术债、spec 或 plan，避免无编号事项。
- 迭代计划不是强制承诺；发现优先级变化时更新状态和原因。
- 不自动创建新迭代：新迭代须另行立项后再登记到本表，本目录不预建 W31。
