## 规划原则

产业园区 AI 落地不走“技术驱动、全面铺开”，而走“战略驱动、精准打击”。先用高价值、数据可控、风险可解释的场景验证平台底座，再逐步扩展到更强自治和更复杂推理。

优先级判断：

| 类别 | 业务价值 | 实现难度 | 策略 |
|------|----------|----------|------|
| P0 合规风控 | 极高 | 中等偏低 | 第一优先级，先守住“不出事”的底线。 |
| P1 创收增收 | 极高 | 中高 | 第二阶段攻坚，适合在底座工具、数据和图谱能力稳定后推进。 |
| P2 降本提效 | 中等 | 低 | 与 P0 同步挑选速赢场景，快速建立业务信任。 |
| P3 战略决策 | 高 | 高 | 长期储备，不作为近期交付承诺。 |

## 原子能力优先级路线

应用越多，越不能按 APP 一个个硬写功能。优先要把共用原子能力打稳，否则后续每个应用都会重复做会话、报告、工具调用、权限、人工确认和指标解释。

| 顺序 | 原子能力 | 关联需求 | 解锁应用 | 说明 |
|------|----------|----------|----------|------|
| 1 | 会话、任务和产物容器 | REQ-041 / REQ-042 / REQ-047 | APP-005 / 018 / 022 / 023 / 029 | 所有业务 AI 都需要保存任务过程、报告草稿、证据、人工确认和历史版本。 |
| 2 | MCP 注册和内部系统契约 | REQ-044 / REQ-048 | APP-005 / 006 / 009 / 012 / 013 / 015 / 021 | 没有统一内部系统 adapter，后续每个应用都会写死接口。 |
| 3 | Skill 注册与 SOP 执行 | REQ-045 | APP-005 / 007 / 012 / 014 / 018 / 022 / 028 | 背调、合同审查、周报、申报、条款抽取都本质是 SOP。 |
| 4 | 智能问数与数据激活 | REQ-052 | APP-005 / 020 / 022 / 023 / 028 | 激活多年信息化系统沉淀数据，解决“业务人员如何安全问内部数据”。 |
| 5 | 业务指标语义层 | REQ-051 | APP-012 / 015 / 020 / 023 / 026 / 028 | 管理层分析和报送材料必须统一指标口径、数据血缘和计算规则。 |
| 6 | 主动任务调度与事件触发 | REQ-049 | APP-006 / 019 / 020 / 024 / 025 / 029 | 支撑每日扫描、到期提醒、风险预警、线索雷达和流程编排。 |
| 7 | 政策 / 规则 / 评分引擎 | REQ-050 | APP-006 / 007 / 009 / 018 / 019 / 020 / 028 | 让推荐、风险、政策匹配和线索评分可解释、可审计、可调参。 |
| 8 | Agentic RAG 编排 | REQ-043 | APP-005 / 010 / 011 / 019 / 029 | 在工具、规则、任务容器稳定后，再做多步规划和失败重试。 |

关键取舍：REQ-052 要前移。国资国企的核心价值不是多接几个外部工具，而是把既有信息化系统里的合同、租赁、财务、工单、招商和台账数据激活。REQ-043 很诱人，但不应第一个做深；没有会话、产物、MCP、Skill、智能问数、调度和规则评分，Agentic RAG 只会变成“会调用工具的聊天框”，难以落进企业流程。

2. 同步塑形平台原子能力。

## APP-006: 租约风险主动预警

业务目标：每日自动扫描在租企业履约数据、外部风险信号和内部欠费记录，按风险等级推送给资产运营和法务。

首期能力：

- 读取租约、账单、缴费、企业主体和合同到期信息。
- 可选调用企查查 MCP 或外部风险接口检查母公司失信、经营异常、司法风险。
- 输出风险等级、触发原因、证据来源和标准处置建议。
- 支持人工确认、关闭、转派和后续跟踪。

非目标：不自动发律师函，不自动终止合同，不替代法务判断。

## APP-007: 标准租赁合同 AI 审核

业务目标：在标准租赁合同审批中自动识别维修责任、免租期、违约责任等条款风险，并给出修改建议和依据。

首期边界：

- 只覆盖标准化租赁合同。
- 对照内部标准合同范本、历史争议案例和规则条款。
- 输出风险条款、建议改法、依据来源和人工确认区。

非目标：非标定制合同仍由人工全量审核，不做自动结论。

## APP-008: 招投标合规审查

业务目标：采购或招投标前识别供应商股权关联、共同实控人和围标风险。

规划判断：合规价值明确，但触发频率低，且需要采购流程集成。先保留 Future，不进入近期工作台。

## APP-009: 招商载体推荐

业务目标：招商人员录入企业行业、面积、配套、租期等需求后，系统从资管库存中推荐匹配载体。

首期能力：

- 调用内部资管 MCP 读取楼宇、厂房、公寓、面积、价格、空置、配套和限制条件。
- 根据企业需求做规则匹配和可解释排序。
- 输出推荐理由、冲突项、可替代方案和招商话术草案。

## APP-010: 招商谈判策略辅助

业务目标：谈判前综合企业支付能力、周边竞品报价、本园区空置压力和产业带动权重，给出谈判策略。

规划判断：价值高但数据依赖重。首期不直接实现，先做数据可得性 Spike 和小范围试点。

## APP-011: 产业链缺口扫描与目标企业推荐

业务目标：输入园区主导产业后，生成产业链图谱、薄弱环节和目标招商企业清单。

规划判断：高度依赖外部产业数据库、融资数据、企业扩产信号和产业研判模型。保留为中长期创收增收候选。

## APP-012: 招商双周报自动生成

业务目标：自动汇总招商 CRM、空间管理平台和政策库数据，生成集团统一模板的招商双周报草稿。

首期能力：

- 拉取核心经营指标、项目进度、去化数据和风险提示。
- 按固定模板生成可编辑草稿。
- 标记缺失数据和需要人工补充的段落。

## APP-013: 载体信息自动录入

业务目标：上传产权证、测绘报告、项目介绍文档后，自动抽取楼层、面积、配套、产权年限等字段，辅助资产初始化。

首期边界：

- AI 只生成待复核草稿。
- 人工确认后再写入资产台账。
- 所有字段保留来源页码 / 段落 / OCR 置信度。

## APP-014: 合同关键条款自动提取

业务目标：批量解析历史租赁合同 PDF，提取承租方、租赁面积、租金标准、免租期、合同到期日等字段，回填资产台账。

首期边界：

- 先覆盖电子合同和清晰扫描件。
- 对低置信字段强制人工复核。
- 输出字段来源和无法识别原因。

## APP-015: 财务核销 AI 匹配

业务目标：读取银行流水、账单和合同规则，自动完成租金、保证金、物业费的预核销匹配。

首期边界：

- AI 只做预匹配和异常标注。
- 财务人工确认最终核销。
- 保留匹配规则、置信度和异常原因。

## APP-016: 产业升级方向研判

业务目标：持续采集宏观产业、政策、人才和区域数据，周期性生成园区产业发展预警与机遇报告。

规划判断：属于战略储备，需要长期数据采购、本体建设和验证机制，不进入近期交付。

## APP-017: 资产证券化分析辅助

业务目标：在资产证券化业务中辅助资产包合规筛查、现金流测算和风险归集。

规划判断：金融专业复杂、合规容错率极低。短期不推荐落地，只保留远期方向。

## 不做清单

- 不把所有产业园区场景一次性排进开发。
- 不把 AI 结果当作准入、投决、法务或财务最终结论。
- 不在缺少内部系统契约时直接做跨系统写入。
- 不把外部数据能力、企查查 MCP 或 Skill 市场能力等同于产品内生产级治理能力。

## 后续塑形规则

- 进入开发前，每个 APP 必须拆成稳定 `REQ-xxx`，并明确验收标准、数据来源、人工确认点和风险边界。
- MCP / Skill 相关应用必须说明依赖 REQ-044 / REQ-045 的程度。
- 高价值但高不确定场景先走 Spike，不直接承诺交付。
- 每个应用必须既能独立访问，也能注册进 AI 应用广场。
