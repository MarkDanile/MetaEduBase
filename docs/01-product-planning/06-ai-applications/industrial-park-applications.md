## 规划原则

产业园区 AI 落地不走“技术驱动、全面铺开”，而走“战略驱动、精准打击”。当前 AI 应用开发以园区为优先纵向，先用高价值、数据可控、风险可解释的场景验证平台底座，再逐步扩展到更强自治、更复杂推理和教育等其他业务纵向。

优先级判断：

| 类别 | 业务价值 | 实现难度 | 策略 |
|------|----------|----------|------|
| P0 合规风控 | 极高 | 中等偏低 | 第一优先级，先守住“不出事”的底线。 |
| P1 创收增收 | 极高 | 中高 | 第二阶段攻坚，适合在底座工具、数据和图谱能力稳定后推进。 |
| P2 降本提效 | 中等 | 低 | 与 P0 同步挑选速赢场景，快速建立业务信任。 |
| P3 战略决策 | 高 | 高 | 长期储备，不作为近期交付承诺。 |

## 原子能力优先级路线

应用越多，越不能按 APP 一个个硬写功能。优先要把共用原子能力打稳，否则后续每个应用都会重复做会话、报告、工具调用、权限、人工确认和指标解释。

| 顺序 | 原子能力 | 关联需求 | 解锁应用 | 说明 |
|------|----------|----------|----------|------|
| 1 | 会话、任务和产物容器 | REQ-041 / REQ-042 / REQ-047 | APP-005 / 009 / 012 / 016 / 030 | 近期五应用都需要保存任务过程、报告草稿、证据、人工确认和历史版本。 |
| 2 | MCP 注册和内部系统契约 | REQ-044 / REQ-048 | APP-005 / 006 / 009 / 012 / 013 / 015 / 016 / 021 / 030 | 没有统一内部系统 adapter，后续每个应用都会写死接口。 |
| 3 | Skill 注册与 SOP 执行 | REQ-045 | APP-005 / 007 / 012 / 014 / 016 / 018 / 028 | 背调、产业研究、报表、合同审查、申报和条款抽取都需要版本化 SOP。 |
| 4 | 智能问数与数据激活 | REQ-052 | APP-005 / 009 / 012 / 016 / 020 / 023 / 028 / 030 | 激活多年信息化系统沉淀数据，解决“业务人员如何安全问内部数据”。 |

## APP-006: 租约风险主动预警

业务目标：每日自动扫描在租企业履约数据、外部风险信号和内部欠费记录，按风险等级推送给资产运营和法务。

首期能力：

- 读取租约、账单、缴费、企业主体和合同到期信息。
- 可选调用企查查 MCP 或外部风险接口检查母公司失信、经营异常、司法风险。
- 输出风险等级、触发原因、证据来源和标准处置建议。
- 支持人工确认、关闭、转派和后续跟踪。

非目标：不自动发律师函，不自动终止合同，不替代法务判断。

## APP-007: 标准租赁合同 AI 审核

业务目标：在标准租赁合同审批中自动识别维修责任、免租期、违约责任等条款风险，并给出修改建议和依据。

首期边界：

- 只覆盖标准化租赁合同。
- 对照内部标准合同范本、历史争议案例和规则条款。
- 输出风险条款、建议改法、依据来源和人工确认区。

非目标：非标定制合同仍由人工全量审核，不做自动结论。

## APP-008: 招投标合规审查

业务目标：采购或招投标前识别供应商股权关联、共同实控人和围标风险。

规划判断：合规价值明确，但触发频率低，且需要采购流程集成。先保留 Future，不进入近期工作台。

## APP-009: AI 载体选址（招商）

业务目标：招商人员输入企业行业、面积、成本、交通、配套、交付时间和政策等需求后，系统融合资产管理系统库存与受治理的外部地理数据，提供多套可比较、可解释、可追溯的选址方案。

首期能力：

- 经 REQ-048/052 读取楼宇、厂房、公寓、面积、价格、空置、配套、交付状态和准入限制。
- 经 REQ-063 调用授权地图、地理编码、交通和公共设施来源，保留坐标系、查询时间、距离/时长口径和证据。
- 将企业需求分为硬约束、偏好和待确认项；硬约束不满足的载体不得因模型偏好进入主推荐。
- 输出至少三套候选方案，比较成本、空间、交通、配套、政策、交付风险和数据缺口。
- 支持招商人员调整权重或补充条件后重新计算，并保留方案版本和变化原因。

首个切片：使用一个授权企业需求、一个真实资产 Catalog 和一个授权地图/交通来源，只做只读决策支持，不自动锁定房源或修改资产系统。

## APP-010: 招商谈判策略辅助

业务目标：谈判前综合企业支付能力、周边竞品报价、本园区空置压力和产业带动权重，给出谈判策略。

规划判断：价值高但数据依赖重。首期不直接实现，先做数据可得性 Spike 和小范围试点。

## APP-012: 招商动态报表 AI 生成

业务目标：面向公司内部、集团和管委会每次不同的数据统计/申报要求，自动识别现有系统已覆盖、可推导、需人工采集和暂不可得的数据，生成缺口采集表单与填报入口，完成汇总报表，并把常态需求沉淀为可复用模板或应用。

首期能力：

- 输入自然语言、Excel/Word 模板或历史报表，生成字段、口径、统计周期、受众和输出格式草案。
- 经 REQ-051/052 判断字段是否已有系统数据、可由已有指标推导、需要人工采集或暂不可得，并展示判断依据。
- 经 REQ-062 生成版本化动态表单、发布填报入口、跟踪进度、修订和缺失项；AI 草案由授权人员审核后才能发布。
- 汇总系统查询与人工填报数据，固定数据快照、表单版本和口径，生成可编辑报表及证据明细。
- 将验收通过的高频 Campaign 提升为周期模板，通过 REQ-049 创建下一期任务、催办和冻结窗口。

首个切片：选择一份真实上报要求，覆盖至少一类系统已有字段和一类人工采集字段，完成“要求解析 -> 覆盖确认 -> 表单发布 -> 多人填报 -> 汇总报告 -> 常态模板”的闭环。

## APP-013: 载体信息自动录入

业务目标：上传产权证、测绘报告、项目介绍文档后，自动抽取楼层、面积、配套、产权年限等字段，辅助资产初始化。

首期边界：

- AI 只生成待复核草稿。
- 人工确认后再写入资产台账。
- 所有字段保留来源页码 / 段落 / OCR 置信度。

## APP-014: 合同关键条款自动提取

业务目标：批量解析历史租赁合同 PDF，提取承租方、租赁面积、租金标准、免租期、合同到期日等字段，回填资产台账。

首期边界：

- 先覆盖电子合同和清晰扫描件。
- 对低置信字段强制人工复核。
- 输出字段来源和无法识别原因。

## APP-015: 财务核销 AI 匹配

业务目标：读取银行流水、账单和合同规则，自动完成租金、保证金、物业费的预核销匹配。

首期边界：

- AI 只做预匹配和异常标注。
- 财务人工确认最终核销。
- 保留匹配规则、置信度和异常原因。

## APP-016: 产业研究辅助平台

业务目标：服务集团产促部门针对区域拟发展的新兴产业开展研究。平台按经确认的产业研究范式组织研究问题、内外部数据、产业链、关键环节和企业分析，生成可向领导汇报的研究报告，并转化为子公司招商人员可执行的方向与目标企业线索。

首期能力：

- 建立研究项目、研究范围、关键问题、时间区间、区域和交付物，不把一次对话当完整研究事实源。
- 通过版本化产业研究 Skill 生成研究计划和任务分解，由研究人员确认后执行。
- 经 REQ-063 采集授权的政策、产业报告、企业、投融资、专利、人才和区域数据，并区分来源事实、AI 摘要、分析假设和人工结论。
- 复用 APP-011 的产业链拆解、缺口分析和目标企业研究能力，但不要求首期引入 Neo4j/GraphRAG。
- 支持研究章节、证据、数据表、图表和报告版本；关键结论必须有证据覆盖和人工审阅状态。
- 将获批研究结论转化为产业方向、目标企业画像、招商关键词和子公司行动建议，发布前经授权人员确认。

首个切片：选择一个真实新兴产业和一套获授权来源，完成“研究问题 -> 计划确认 -> 内外部采集 -> 产业链/企业分析 -> 报告审阅 -> 招商指导”的单项目闭环。

## APP-017: 资产证券化分析辅助

业务目标：在资产证券化业务中辅助资产包合规筛查、现金流测算和风险归集。

规划判断：金融专业复杂、合规容错率极低。短期不推荐落地，只保留远期方向。

## APP-030: 会展招商 AI 工具

业务目标：围绕每次展会建立独立招商采集 Campaign，复用历史模板并适配本次领导关注字段，让百人级招商人员通过表单或对话登记企业线索，最终形成可查看、可追溯、可导出的整体招商成果。

首期能力：

- 创建展会、组织范围、招商人员、采集周期和管理口径；从历史模板复制后生成本次 `FormSchemaVersion` 草案。
- 授权人员可增删本次特有字段并确认必填、枚举、证明材料、可见范围和统计口径，发布后不原地修改历史版本。
- 招商人员可在移动端表单填报，也可在 Conversation 中自然语言登记；Agent 将内容映射为字段候选，逐项确认和校验后写入同一 Submission contract。
- 支持企业主体标准化、重复线索识别、归属冲突提示、缺失字段追问和修订历史，不自动裁决招商归属。
- 管理端查看人员/团队进度、线索数量、行业/区域分布、重点项目和缺失项；汇总结果固定快照并生成领导报告。
- 历史展会模板、字段和已授权字典可复用，但不同展会 Campaign、Submission 和权限完全隔离。

首个切片：选择一个真实展会和一组受邀招商人员，完成“模板复用 -> 本次字段调整 -> 发布 -> 表单/对话登记 -> 去重与补全 -> 领导汇总”的闭环；规模测试覆盖百人级受众，但不要求首期模拟真实百人同时在线峰值。

## 不做清单

- 不把所有产业园区场景一次性排进开发。
- 不把 AI 结果当作准入、投决、法务或财务最终结论。
- 不在缺少内部系统契约时直接做跨系统写入。
- 不把外部数据能力、企查查 MCP 或 Skill 市场能力等同于产品内生产级治理能力。

## 后续塑形规则

- 进入开发前，每个 APP 必须拆成稳定 `REQ-xxx`，并明确验收标准、数据来源、人工确认点和风险边界。
- MCP / Skill 相关应用必须说明依赖 REQ-044 / REQ-045 的程度。
- 高价值但高不确定场景先走 Spike，不直接承诺交付。
- 每个应用必须既能独立访问，也能注册进 AI 应用广场。
