## 背景

国有产业园区招商和投决场景中，企业准入前背调是高价值、强刚需、风险可感知的合规风控环节。当前企查查 MCP 已在 Codex 环境中可用，企查查 Skill 市场也提供了可复用的尽调 / 背调类 SOP 能力。项目侧需要把这些能力产品化为一个可归档、可审计、可接入内部系统的企业 360 背调工作台。

本需求不是简单的“问企业风险”，而是验证平台三项关键能力：

- 第三方 MCP 接入能力：接入企查查 MCP，获取工商、司法、股权、风险和经营公开事实。
- Skill 执行能力：复用或导入企查查官方 Skill / SOP，生成标准化背调报告。
- 内部 MCP 接入能力：读取园区内部客户信息，如租赁、缴费、合同、工单和历史合作记录。
- 智能问数能力：通过语义层、查询计划和 SQL Guard 激活国资园区多年信息化系统沉淀的结构化数据。

## 关键边界

- Codex 当前能调用企查查 MCP，只说明本地 AI IDE 已具备工具入口；产品后端仍需要自己的 MCP 注册、权限、调用、审计和错误处理能力。
- 企查查数据只能作为事实来源和风险排查依据，不能替业务系统直接做“准入 / 不准入 / 投决通过”最终决策。
- 若用户输入企业简称、品牌名、股票简称或不完整名称，必须先走企业实体识别并由用户确认主体，不能自动补全后直接调用下游工具。
- 背调报告必须区分“事实数据”“AI 分析”“待人工确认项”“人工复核结论”。

## 用户与场景

| 用户 | 使用目标 |
|------|----------|
| 招商人员 | 在企业初筛、拜访前或入驻申请前快速形成企业背调材料 |
| 投资 / 投决人员 | 在投决会前获取可归档的企业背景与风险摘要 |
| 管理层领导 | 快速查看企业准入关注点、风险信号和人工复核结论 |
| 法务 / 风控 | 查看风险事实、证据来源和待人工确认项 |

## V0 流程

```text
输入企业名称 / 统一社会信用代码
  -> 企业主体识别与确认
  -> 调用企查查 MCP 获取外部事实
  -> 调用内部 MCP 或 mock 获取园区内客户历史信息
  -> 智能问数查询内部结构化经营 / 履约 / 工单 / 合同数据
  -> 背调 Skill 按 SOP 组织分析和报告结构
  -> 生成企业 360 背调报告草案
  -> 人工补充 / 确认 / 归档
```

## 数据来源

| 来源 | 说明 | V0 处理 |
|------|------|---------|
| 企查查 MCP | 工商登记、股东、实控人、UBO、风险扫描、司法 / 经营相关事实 | 使用 adapter 封装，记录工具调用 trace |
| 企查查 Skill | 背调报告 SOP、分析维度和报告结构 | 先作为 Skill 模板 / SOP 输入，后续接入 Skill registry |
| 内部 MCP | 园区租赁、缴费、合同、工单、历史合作、客户状态 | V0 可先定义契约并使用 mock，真实系统后续接入 |
| 智能问数 | 对内部结构化数据做语义层查询、指标口径解释、SQL 安全和结果摘要 | 作为 REQ-052 原子能力；REQ-046 V0 可先接最小问数样例或 mock |
| AI Chat / Workbench | 会话、任务、报告产物、证据链和人工确认 | 依赖 REQ-041 / REQ-042 逐步增强 |

## 报告结构

1. 企业基础信息
2. 股权与实控人结构
3. 受益所有人与关联关系
4. 外部风险扫描摘要
5. 司法、行政、经营、舆情等公开风险事实
6. 内部租赁、缴费、合同、工单和历史合作记录
7. 综合风险关注点
8. 招商 / 投决关注问题清单
9. 证据来源与工具调用记录
10. 人工复核结论区

## 验收标准

| ID | 内容 |
|----|------|
| AC-1 | 输入完整企业名称或统一社会信用代码时，系统可直接进入主体确认；输入简称时必须先展示候选主体并等待用户选择。 |
| AC-2 | 外部事实通过企查查 MCP adapter 获取，工具调用名称、参数、返回摘要、错误和时间戳可追踪。 |
| AC-3 | 内部客户信息通过内部 MCP 契约获取；真实系统未接入前，mock 数据结构必须与契约一致。 |
| AC-4 | 至少 3 个内部智能问数样例能进入报告 evidence：历史租赁 / 欠费缴费 / 工单或合同义务；真实系统未接入前必须标记 mock。 |
| AC-5 | 背调 Skill 能按固定 SOP 生成报告草案，报告结构稳定，不把事实、AI 分析和人工结论混写。 |
| AC-6 | 报告中所有关键风险事实能追溯到企查查 MCP、内部 MCP、智能问数结果或用户上传 / 系统已有材料。 |
| AC-7 | 报告只给“风险关注点 / 待人工确认项 / 辅助分析”，不输出最终准入或投决结论。 |
| AC-8 | 工具不可用、企业未匹配、字段缺失或内部数据未接入时，报告明确标注缺失原因，不编造默认值。 |
| AC-9 | 至少用 1 个用户确认的样例企业完成端到端演示：主体确认 -> 外部事实 -> 内部问数 -> 报告草案 -> 人工确认区。 |

## 非目标

- 不在本需求里实现招投标合规、租约预警、合同 AI 审核或招商载体推荐。
- 不直接实现通用 MCP 平台全部能力；通用治理仍归 REQ-044。
- 不直接实现通用 Skill 市场全部能力；Skill registry 仍归 REQ-045。
- 不用 AI 取代投决、准入、风控或法务最终判断。
- 不把 Codex 线程内的 MCP 工具当作生产后端依赖。
