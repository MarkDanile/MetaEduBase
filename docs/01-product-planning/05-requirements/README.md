# Requirements — 可塑形需求

本目录只放值得进一步澄清的需求。早期想法先留在 `docs/01-product-planning/04-backlog.md`；进入交付前，再按需要迁入或镜像到 `docs/02-delivery-plans/01-specs/*`。

## 何时新建

- 需求价值明确，但范围、角色、验收标准还需要塑形。
- 需求可能跨多个模块、多个页面或多个迭代。
- 需要在进入 superpower / compound-engineering-plugin / plan-do 前固定上下文。

## 模板

```md
# REQ-xxx: 需求标题

Status:
Priority:
Milestone:
External:

## Problem

## Users / Scenarios

## Scope

## Acceptance

## Open Questions

## Delivery Links
```

当需求进入开发，`Delivery Links` 应指向对应 `docs/02-delivery-plans/01-specs/*`、`docs/02-delivery-plans/02-plans/*`、`current-work.md` 任务卡或 PR。
