## 背景

国资国企过去多年投入了大量信息化系统，沉淀了招商、资管、合同、财务、工单、OA、报表和台账数据。AI 应用的关键价值不是只接外部工具，也不是只做文档 RAG，而是把这些结构化数据真正激活，让业务人员能用自然语言查询、解释和复用内部经营数据。

企业 360 背调是首个高价值场景：外部企查查事实只能回答“这家公司在外部世界是什么样”，但国资园区真正关心的是“这家公司和本园区发生过什么、履约如何、欠费如何、工单投诉如何、合同义务是否异常、历史合作评价怎样”。这些问题必须通过内部数据智能问数能力支撑。

## 目标

建设一套可复用的智能问数原子能力，让 AI 应用可以在权限受控、口径明确、结果可解释的前提下查询结构化业务数据。

核心目标：

- 将自然语言问题映射到受治理的数据集、指标、维度、过滤条件和 SQL / 查询计划。
- 通过语义层屏蔽物理表结构复杂度，避免大模型直接猜表、猜字段、猜口径。
- 在查询前做权限、敏感字段、SQL 安全和成本控制。
- 在查询后给出结果解释、数据来源、指标口径和异常提示。
- 支撑企业 360 背调、续约风险、报送材料、经营分析、空置去化和政策匹配等上层应用。

## 能力边界

| 层级 | 能力 | 说明 |
|------|------|------|
| 数据接入层 | 数据源连接与只读查询 | 首期以 PostgreSQL / 业务库只读视图为主，后续扩展数据仓库、Lakehouse、BI dataset。 |
| 语义层 | 业务实体、指标、维度、同义词、口径 | 定义企业、合同、租约、账单、工单、楼宇、载体、招商项目等实体与指标。 |
| Query Planner | 自然语言到查询计划 | 先生成结构化 query plan，再生成 SQL，避免直接裸 Text-to-SQL。 |
| SQL Guard | SQL 安全、权限、成本和执行限制 | 禁止写操作、跨租户越权、敏感字段泄露、无界全表扫描。 |
| Result Explainer | 结果解释和来源引用 | 返回表格、摘要、指标口径、过滤条件、SQL 摘要和置信提示。 |
| Evaluation | 问数样例和回归集 | 建立真实业务问题样例，不只测 response shape。 |

## 与 RAG / MCP / 指标语义层的关系

| 能力 | 关系 |
|------|------|
| RAG | 适合文档、政策、合同条款、制度说明等非结构化文本；不适合替代经营数据精确查询。 |
| MCP | 提供跨系统工具调用和权限边界；智能问数可以通过内部 MCP 或只读数据视图访问数据。 |
| REQ-048 | 定义内部系统 adapter 契约，解决“数据从哪里来”。 |
| REQ-051 | 定义经营指标口径，解决“出租率、欠费率、NOI 等怎么算”。 |
| REQ-052 | 定义自然语言问数、查询计划、SQL 安全和结果解释，解决“业务人员如何问”。 |

## 企业 360 背调中的首期问题

REQ-046 至少要能由智能问数支撑以下内部问题：

| 问题 | 数据范围 | 输出要求 |
|------|----------|----------|
| 这家公司是否曾入驻本园区？ | 客户主数据 / 租约 / 合同 | 返回主体匹配、历史租赁记录、时间范围和来源。 |
| 过去 3 年是否有欠租、欠费或保证金异常？ | 账单 / 流水 / 应收应付 | 返回金额、期间、费用类型、当前状态和口径说明。 |
| 是否有高频投诉、维修或服务工单？ | 工单 / 客诉 / 物业系统 | 返回工单类型、数量、处理状态和异常摘要。 |
| 合同是否存在即将到期、违约、免租期或递增租金义务？ | 合同 / 租约 / 条款抽取结果 | 返回关键义务、到期时间和待人工确认项。 |
| 历史合作评价如何？ | 拜访记录 / 合作备注 / 人工评价 | 区分结构化事实和人工备注，不把主观评价伪装成事实。 |

## 推荐实现路径

### Slice 0: 数据问数盘点

- 盘点首批数据源：资管、招商 CRM、合同、财务缴费、工单。
- 识别只读视图、可查询字段、敏感字段和权限边界。
- 为企业 360 背调挑选 10 到 20 个真实问数样例。

### Slice 1: 语义层最小模型

- 建立业务实体：企业、客户、合同、租约、账单、楼宇、载体、工单。
- 建立指标：欠费金额、欠费次数、合同数、租赁面积、工单数、到期天数、续约状态。
- 建立同义词：欠租 / 欠费 / 应收未收，载体 / 房源 / 单元，客户 / 企业 / 承租方。

### Slice 2: 查询计划优先

- 用户自然语言先转为结构化 query plan。
- query plan 包含实体、指标、维度、过滤、时间范围、排序、limit。
- 只有 query plan 校验通过后才生成 SQL。

### Slice 3: SQL Guard 与权限

- 强制只读查询。
- 禁止无 limit 的明细查询。
- 禁止跨租户、跨组织越权。
- 敏感字段默认脱敏或拒绝。
- 记录查询人、问题、query plan、SQL 摘要、执行时间和结果行数。

### Slice 4: 结果解释与证据

- 返回表格结果、自然语言摘要、指标口径、过滤条件和数据来源。
- 对空结果、字段缺失、权限不足、口径不明确进行明确提示。
- 支持把问数结果作为报告 evidence_ref 进入 REQ-046 报告。

### Slice 5: 回归样例与业务验收

- 建立企业 360 背调问数样例集。
- 验证同义问法、时间范围、主体匹配、权限拒绝、空结果和高风险 SQL。
- 不允许只测试接口 shape，必须验证结果含义和口径。

## 验收标准

| ID | 内容 |
|----|------|
| AC-1 | 至少登记 3 类内部业务数据源及其只读访问边界。 |
| AC-2 | 至少建立企业、合同、租约、账单、工单 5 类核心语义实体。 |
| AC-3 | 自然语言问题必须先生成 query plan，再生成 SQL；query plan 可被记录和人工审查。 |
| AC-4 | SQL Guard 能阻止写操作、无界查询、越权查询和敏感字段泄露。 |
| AC-5 | 问数结果返回数据表、摘要、指标口径、过滤条件和数据来源。 |
| AC-6 | 企业 360 背调能把内部问数结果作为 evidence_ref 写入报告。 |
| AC-7 | 至少 10 个真实业务问数样例通过回归验收，覆盖成功、空结果、权限不足和字段缺失。 |

## 非目标

- 不在首期替代 BI / 数据仓库 / 主数据平台。
- 不允许大模型直接对生产库裸写 SQL 并执行。
- 不在权限不清楚时查询敏感经营数据。
- 不把问数结果当作不可质疑的最终经营结论；关键结论仍需展示口径和来源。
- 不要求首期支持所有数据库和所有业务系统。

## Open Questions

- 首批智能问数对接哪个数据源：资管系统、财务缴费、招商 CRM、合同系统，还是先建只读样例库？
- 是否已有集团统一指标口径、数据字典或 BI dataset 可复用？
- 企业主体如何与内部客户主数据匹配：统一社会信用代码、企业全称、历史名称还是人工映射？
- 哪些字段属于敏感字段，需要脱敏、拒绝或仅管理层可查？
